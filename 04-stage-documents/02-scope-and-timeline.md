# 包含什么

- 4个主页面：首页、Services、Datasets、Research。
- 12个数据集详情页：共用基础模板，按两类内容适配。
- 桌面/移动端、导航、页脚、现有联系及样本申请表单。
- 含共同设计、3张首页数据集插画、1组轻量首屏动效及公共交互。

基于现有网站和表单改版，保留粉色、Logo及文案；文案调整需客户确认。不含外部报名页面和独立网站。

## 共同设计：三次沟通，逐步定稿

三次沟通，每次提供两种方向，共同校准配色、字体、布局与插画风格，按反馈逐步确定一个最终方案。

- 第一次｜探索：了解品牌、受众与审美偏好，对比两种初步方向及插画示意，确定风格。
- 第二次｜深化：根据反馈对比两种调整方向的布局、细节与插画，确认保留和修改项。
- 第三次｜定稿：在已选风格内比较两种细化方案，完成调整，确认页面与插画。

含3张首页数据集插画的生成、筛选及随三次沟通调整，匹配业务与页面风格；交付一个确认方向的代码稿和选定插画，供后续开发。

## 1. 正式业务诊断报告

覆盖OrphLux现有4个主页面、12个详情页及共用模板。正式报告列明问题、检查依据（必要截图或记录）、业务影响、修改建议与优先级，区分已确认和待客户补充资料的事项。

- 搜索表现：获授权后分析Google展示、点击和自然访问，定位展示多、点击少的页面；缺少历史数据时注明限制，不推测流量或效果。
- AI表现：围绕品牌、服务及客户常见问题，检查可访问的Google AI回答、ChatGPT、Perplexity、Gemini，记录提及情况、描述准确性、引用来源、问法与时间。
- 站内检查：逐项诊断下表七类内容。
- 业务机会：检查内容缺口、公开品牌信息及必要的域名历史线索，提出优先建议；新增页面和站外工作单列，不自动纳入代码修改。

## 2. 接管代码后的站内修改

取得可运行代码、权限及确认的业务资料后，复核问题并按报告形成修改清单，落实下表适用项目。限现有16页、共用模板及网站配置；不适用项注明原因。

| 修改项目 | 包含的具体工作 |
|-|-|
| 页面入口与标题 | 修正菜单、按钮及站内链接，便于搜索引擎发现内容；整理主标题和层级，避免误用页脚、弹窗文字作为主题。 |
| 搜索结果中的展示 | 梳理现有页面关键词，调整搜索标题与简介，与实际服务及数据集内容一致。 |
| 网址与手机访问 | 核对主要、重复及手机网址的对应关系，修正地址、跳转和重复页面设置；不额外新建独立手机版。 |
| 搜索引擎能否读到完整内容 | 对比访客与搜索引擎读到的内容，修复代码导致的标题、业务说明或关键数据缺失；平台、服务器设置与现有负责人配合处理。 |
| 公司与业务信息 | 按客户确认资料统一服务范围、联系方式和业务描述；补充搜索引擎可识别的公司、服务与页面信息。价格、评价等仅用真实且适用的数据。 |
| 网站页面清单与访问规则 | 整理网站页面清单（sitemap），核对地址和更新时间；解除对重要页面的误拦截，避免无价值搜索页、重复页被反复收录；按客户意愿设置AI读取规则。 |
| 图片、加载与按钮识别 | 补充信息性图片说明，按诊断优化图片大小、加载及可调整的多余脚本，减少页面跳动；为必要按钮补充名称，便于辅助工具和AI识别。 |

## 3. 修改后的检查与交付

- 交付修改代码、预览网站、修改记录及必要备份说明，经客户确认后配合上线。
- 逐项复查，列明“已完成、待客户配合、不适用”，附必要前后对比；修复本次修改造成的问题。
- 权限齐备后配置或核对Google Search Console、提交页面清单；说明后续观察搜索点击、网站访问和AI表现的方法。
